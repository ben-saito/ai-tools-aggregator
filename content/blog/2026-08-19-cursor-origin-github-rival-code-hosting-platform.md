# Cursor、GitHubの不振に乗じて競合コード Hosting プラットフォーム「Origin」を開始

Cursorは、AI Code Editorで知られるAIスタートアップ企业（现已成为SpaceX旗下企业）が、GitHubの代替となるコード Hosting プラットフォーム「Origin」を今週 开始した。GitHubは长年かけて開発者に好まれてきたコード Hostingプラットフォームだが、近年は広く报告されている障害とパフォーマンス低下に苦しんでいる。

---

## Origin の概要

Originは、共同でのコードbases作業、浏览・編集、Pull Request 管理、リポジトリ存储など、GitHubで通常行われるすべてのコンテンツを涵盖する。Cursorによると、Originの最も注目すべき特長の1つは、GitHubとの相互運用性だ。ユーザーはGitHubから完全に移行する必要はなく、OriginとGitHubの間でコードを往来できる。

「GitHubリポジトリはCursor Hostingのリポジトリと並行して配置できます」とCursorはブログ記事て説明。「GitHubをCursorに接続し、組織を選択して、同期可能なリポジトリを確認できます」

---

## GitHub の障害がCursorの商機を後押し

Originの開始は、GitHubに対する不満が頂点に達した時期と重なる。Originがlaunchされたのと同じ日に、GitHubは長い全世界的な障害に見舞われた。6時間以上わたって、サイトの機能が低下し、世界中で約20%的エラー率が発生したという報告がある。

LeadDevの最近の分析によれば、GitHubは過去1年間で約257件の障害を報告している。Charles Humble記者が「著名ユーザーの目に見える脱出」と表現したように。こうした継続的な問題がGitHubからの移行を急ぎたいユーザーに火をつけている。

---

## 180 Million ユーザーの壁

それでもCursorの挑戦は大きい。GitHubの独自metricによると、2025年10月時点で約1億8,000万の開発者がプラットフォームを利用している。2007年に設立され、2012年にMicrosoftに買収された同プラットフォームは、世界の最重要的コード Hostingプラットフォームであり続けている。

CursorはOriginで「エージェントネイティブ」機能を間もなく提供する予定だが、詳細は明かされていない。また、より広範囲なコーディング作業をサポートする「アプリエコシステム」の構築も進めているという。
