## MicrosoftがOSSフレームワーク「SkillOpt」を公開：モデル重みを変更せずAIエージェントのスキルを自動最適化

Microsoft Researchが、AIエージェントのスキルドキュメントをモデル重手を触れずに自動最適化できるOSSフレームワーク**SkillOpt**（MITライセンス）を公開した。

###なぜ重要か

AIエージェントスキルは`.md`ファイル形式で保存された命令セットであり、エージェントの振る舞いを重みを変えずにカスタマイズできる。だがその最適化は手作業が主流で、性能向上が保証されないという構造的課題があった。

### アプローチ：深層学習の制御をテキストに適用

SkillOptの核心は、テキストドキュメントの最適化に**深層学習的な制御機構**（学習率、検証ゲート、モメンタム）を導入する点にある。

```python
# 最適化ループの概念
1. 対象モデルがタスクバッチを実行 →実行軌跡を生成
2. オフラインオプティマイザが成功/失敗を分離
3. 構造的編集（追加/削除/置換）を提案
4. 編集予算（学習率相当）で候補を制限
5. 検証セットで評価 →改善なら採用、悪化なら拒否バッファへ
```

重要なのは、**編集予算**が「ステップサイズ制御」として機能し、スキルが前回状態から大きくズレることを防ぐ点だ。検証セットへの厳密な評価は、「 звучит reasonable」（筋が通って見える）テキスト編集でも数学的に性能向上なければ却下する。

### ベンチマーク結果

- GPT-5.5 + Codexで**+23.5ポイント**向上（vs スキルなしベースライン）
- 1BモデルのGPT-5.4-nanoはマルチモーダルQAでスコア**約2倍**、身体性インタラクションで**3倍**
- コード理解スキル（Codexで訓練）をそのままClaude Codeに移植：**+59.7ポイント**

訓練コストはコミュニティフレームワーク（GBrain等）で1タスクあたり**$1〜5**程度。最終スキルは最大2,000トークン、中央値約920トークンで人間によるレビューが容易。

**参考**: [Microsoft/SkillOpt - GitHub](https://github.com/microsoft/SkillOpt)

## コンテキスト圧縮が本番対応に：LCLMでLLM入力を16倍削減・精度劣化ほぼなし

NYU、Columbia、Princeton、University of Maryland、Harvard、Lawrence Livermore National Laboratoryの研究チームが、**LCLM（Latent Context Language Models）** を発表。入力コンテキストを16倍圧縮しながら精度劣化を最小限に抑えた。

### 技術的アプローチ

従来のKVキャッシュ圧縮が「まずフルKVキャッシュを実体化してから evict」という2段階だったのに対し、LCLMは**デコーダープレフィル前に入力トークン列そのものを圧縮**する。

```
アーキテクチャ: 0.6Bエンコーダ + 4Bデコーダ
トレーニング: 3500億トークン以上
- 継続プレトレーニング（圧縮/非圧縮スパン交互）
- SFT（推論・長コンテキストタスク）
- 補助的再構成タスク（エンコーダの詳細保持強化）
```

### ベンチマーク性能

|圧縮率 | RULER精度 | KVキャッシュ比 |
|--------|----------|--------------|
| 圧縮なし | 94.41% | 1x |
| 4x | 91.76% | -3%未満 |
| 16x | 75.06% | 8.8x高速化 |

16x圧縮で入力の93.75%が削減される一方、KVキャッシュ手法全種類より高精度。GSM8Kでも全圧縮率で他社手法を上回った。

### 実用上のポイント

- 既存のLLMと**単純に=swap可能**（RAGパイプラインに組み込み可能）
- 推論トレースのオンライン圧縮には未対応（今後課題）
- 開発者はRAGシステムの再調整が必要

**参考**: [LCLM論文（arXiv）](https://arxiv.org/pdf/2606.09659)

## Visa × ChatGPT統合：AIエージェントが自律的に小売購入を完了

VisaがChatGPTへの決済インフラ統合を発表。AIエージェントが**ユーザーのプロンプトを処理→Merchantカタログ評価→Visa決済レールで精算**までを一気通貫で実行可能になった。

### 技術的差分

従来の小売AI統合は単一ベンダー閉ループ環境が中心だった。Visaの統合は以下を可能にする：

- オープンWebのLLM推論能力を通用的な決済ネットワークに直接接続
- ユーザーが「○○を買って」と命じれば、モデルがベンダー選択・商品比較・金融決済を自動実行
- 人間のバイヤーが零售店のウェブサイトを一切経由しない取引が 증가

### 開発者への影響

AIエージェントは表示広告やUI最適化を評価しない。**構造化メタデータ**（技術仕様、集約されたセンチメントスコア、定价構造）のみが評価基準となる。

結果は明白：**SEOからLM最適化へ**。高品質な構造化メタデータを持たないMerchantは、AIエージェントの検索から見えなくなる。

## GPT-5.5がClaude Fable 5を上回る：新生Agent向けベンチマーク「ALE」公開

UC BerkeleyのCenter for Responsible, Decentralized Intelligence（RDI）をはじめ300人以上の領域専門家が、**Agents' Last Exam（ALE）** を公開。55業種・1,490タスクの厳密な_agentic_労働評価ベッドマークだ。

###評価アーキテクチャ

ALEは5層 функционаленマップ（Brain/Eyes/Body/Hands/Feet）を持ち、エージェントはLinux/Windows VMを視覚导航しながらシェル스크립トとポイント＆クリック操作を交替実行する。

- **LLM-as-a-judge依存:6.8%のみ**（大半は決定的コード評価）
- ベンチマーク汚染防止：全体の約10%のみ公開、残りは非公開でローリング入れ替え

###  리더ーボード

| 順位 | Harness |モデル | Pass Rate |
|------|---------|-------|----------|
| 1 | Codex | GPT-5.5 | 24.0% |
| 2 | Ale Claw | GPT-5.5 | 23.0% |
| 3 | Claude Code | Claude Fable 5 | 22.0% |
| 4 | OpenClaw | GPT-5.5 | 21.1% |
| 5 | Cursor CLI | composer-2.5 | 20.4% |

最难ティア「Last-Exam」ではClaude Opus 4.8もGemini CLIも**0.0%**。現在の最高性能モデルでも実際の労働任務実行は24%どまりという厳しさが明らかになった。

## 1,500ドルで基盤モデルを訓練：SapientのHRM-Text

Sapient Intelligenceの研究チームが、**HRM-Text**（Hierarchical Recurrent Model）を発表。1Bパラメータモデルを約**1,500ドル・1.9日・16GPU**で訓練し、MMLU 60.7%、GSM8K 84.5%を達成した。

### アーキテクチャ革新

HRMは標準Transformerとは 달리、**慢速戦略層（H-module）** と**高速実行層（L-module）** を分離。L-moduleがローカル反復改善、H-moduleが跨サイクルの安定セマンティックコンテキストを維持する。

訓練不安定性を解決するため：
- **MagicNorm**：多想ループでも内部信号を安定させる专门正規化
- **ウォームアップ法**：訓練初期は短く淺い推論ループのみ評価し、徐々により深いシーケンスへ移行
- **タスク完了目的関数**：プロンプト全体の再構成ではなく応答全体を奖励

### 企業にとっての意味

40Bトークン（標準LLMの100〜900分の1）で競争力ある性能が得られる，意味着企業は以下のパターンを検討できる：

- proprietaryデータに触れずに社内の推論コアを低コスト訓練
- 外部検索システムでfactualナレッジをfetchし、モデル自体は推論エンジンとして專門化

```
 критичность: HRM-Textは「すぐにChatGPTの交換品」ではない
 →テンプレート設計、モード選択、アテンションマスキング、アライメント調整が企業チームの主な作業
```
