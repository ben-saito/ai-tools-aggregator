# 輸出管理はなぜいつも失敗するのか——PGPからMythosまで30年の知見

2026年6月、Anthropicの **Fable 5** と **Mythos 5** に対する米国政府の輸出管理が発動された直後、TechCrunchは「PGPからMythosへ：輸出控制在历史上为什么谁都止められなかった」という分析記事を掲載した。過去30年間、暗号化ソフトウェア（PGP）、スパイウェア工具、そして今日のAIモデル——輸出管理は技術革新を止めることなく、議論を呼び続けている。歴史的な視点と技術的論点から、この問題を考える。

---

## 歴史回顾：3度の「無効だった」輸出管理

### 第1波：PGP（1990年代）

1990年代、米政府は強固な暗号化技術を出力規制対象「兵器」に指定した。PGP（Pretty Good Privacy）はそんな中、世界中に広がった。Phil Zimmermannが始めたプロジェクトであり、政府はPGPの国際的な広がりを止められなかった。

**教訓**：強い暗号化が「危険」と認定されたが、民間の需要はそれを上回り世界標準になった。規制は技術の普及を止めることができず、国内産業の競争力を削いだ可能性がある。

### 第2波：スパイウェア・エクスプロイト工具（2000〜2010年代）

2010年代、NSO GroupのPegasusなどに代表されるスパイウェアが深刻な人权侵害に使用されたが、輸出管理や国際規範はこれらの инструмент の拡散を止められなかった。代わりに、責任ある国・企業とそうでないところの格差が生まれただけだった。

**教訓**： spywareの規制は、国家支援の攻撃者可にはほぼ无效で、民間セキュリティ研究社区全体の國際協力環境を悪化させることになった。

### 第3波：AIモデル（現在進行中）

AnthropicのMythosは、**脆弱性の発見能力と悪用能力の両方**を持つとして輸出管理が適用された。「サイバー_security モデル」が国家安全保障上の脅威と見なされた最初の事例の一つである。

Mythosは、软件の脆弱性を自動的に発見し、その脆弱性を攻撃コードとして実装する能力を持つ。Anthropicは当初、「Project Glasswing」という限定的なコンソーシアム形態でpreviewを提供しており、この枠組みの中でも十分に管理できると考えられていた。

しかし、Anthropicが韓国の通信事業者とパートナーシップを結んだ際、米政府高官が懸念を表明。商務省からの通知から90分以内という非常に短い時間で、Anthropicは全ユーザーからのアクセス遮断を迫られた。

## なぜ輸出管理は技術拡散を止められないのか

TechCrunchの分析が指摘するのは、**デジタル技術の特性**にある：

### 1. 複製コストがゼロに近い

ソフトウェアやモデルの重みは、ファイルをコピーするだけで移動できる。物理的な「物品」と異なり、税関で差し押さえることが原理的に難しい。

### 2. 分散化が前提の設計

インターネット時代の技術ツールは、分散型アーキテクチャを前提に設計されている。1つの国・企業・サーバーに依存しないため、あるパスが規制されても別のルートで広がる。

### 3. 「危険な利用」と「正常な利用」の境界が曖昧

Mythosの脆弱性発見能力が「国家安全保障上の脅威」とされる一方で、同じ能力が：
- 企業のセキュリティ診断
- オープンソースソフトウェアの安全確保
- 病院のインフラ保護

に使われることもある。輸出管理令はこれらの正常な利用も一緒に止めてしまう。

### 4. 科学的・技術的国际协调の必要性

セキュリティ研究は本质上、国際的な協調が必要だ。ある脆弱性を「発見」しても、それを「修正」するには世界中の研究者との協力が不可欠だ。輸出管理は、この協調の基盤を切り崩す。

## サイバーセキュリティコミュニティの懸念

複数の有名研究者が連名で公開書簡を发表し、以下のリスクを指摘した：

### 問題の早期発見が止まる

外国籍研究者がMythos/Fableにアクセスできなくなると、悪用可能性の共同発見が困難になる。輸出管理の「 security向上」という当初目的は、逆に inverse，成为風險増大の原因となりうる。

### 中国・ロシアの研究者との協調が止まる

 реальный 脆弱性研究では、「敵」と見なされる国研究者との非公式協調が効果的な防御の鍵になることがある。輸出管理令はこの協調渠道を閉ざす。

### 「輸出管理履歴」の无效性

PGP、スパイウェアに続き、3度目の「失敗」が始まることを、多くの研究者が確信している。

## 替わりとなりうるアプローチ

専門家が示唆するのは、輸出管理よりも**実効性がある**とされる枠組みだ：

| アプローチ | 説明 | 輸出管理との比較 |
|---|---|---|
| **才能ある研究者へのvisa政策** | 最先端AI研究者に米国への移動を鼓励し、人才の流出を防ぐ | 拡散防止ではなく、人才の呼び寄せ |
| **安全基準の國際標準化** | NIST ISO 27001のような枠組みをAIモデルに適用 | 規制より協調・獎励金型 |
| **APIベースのアクセス制御** | モデル本体ではなく、API経由のアクセスに条件を付ける | 複製阻止より、利用履歴の監視に向く |
| **Red Team評価の義務化** | 発売前に независимые 第三者によるsecurity評価を義務付ける | 拡散阻止ではなく、品質保証 |

## 開発者にとっての意味

AI coding Agentを活用する開発者にとって、この輸出管理令は直接的な影響を及ぼす：

- **Claude Code / Claude Agent SDK**：Anthropicの主力製品が「外国籍ユーザー」に如何なる制約を受けるか、現時点では不明
- **モデルの自作リスク**：自有データのファインチューニング用にカスタムモデルを構築する企業にとって、同様の管理対象が広がる可能性
- **API依存のリスク**：単一のモデル提供元に依存することの 政治リスク

輸出管理の行く末とは无关系に、**モデルの分散化・マルチ提供商戦略**は、開発者にとって今季の重要な技術的意思決定テーマであることに変わりはない。
