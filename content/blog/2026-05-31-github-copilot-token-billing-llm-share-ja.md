# GitHub Copilotが月額制からトークン課肌に移行——開発者コストの構造変化とAIエージェントの権限問題

2026年5月最終週から6月初頭にかけて、AI開発ツールチェーンにおいて2つの重要な構造変化が起きている。1つはGitHub Copilotの料金体系刷新——月額固定制からトークン消費ベースのモデルへの移行が完了近づき、小規模チームや個人開発者のコスト構造が大きく変わる。もう1つはエンタープライズAIエージェントの出現に関わる新しい課題——モデルの性能ではなく、権限とガバナンスの層が実際のボトルネックになっているという発見だ。Salesforceの事例には、開発組織の生産性が79%向上した報告も含まれている。

---

## GitHub Copilotのトークンベース課金——「月額制の黄金時代」が終わる

TechCrunchが5月30日報じたように、GitHub Copilotが新しいトークンベースの課金体系に移行し、開発者コミュニティから「M jokes」（皮肉を言う）等強い反発が巻き起こっている。

### 新しい課金の仕組み

従来の月額制（1ユーザーあたり月額10ドルまたは年額100ドル）では、一定の利用量までは追加料金なしで使えた。新しいトークンベースモデルでは、入力トークンと出力トークンの消費量に応じて料金が発生する。

この変更に開発者たちが「M jokes」と反応したのは、小規模プロジェクトや個人開発者にとって、成本予測が困難になるからだ。月額制であれば利用量に関わらず同じ費用だったが、トークン課金は実際の使用量に応じて変動する。忙しい月は請求額が跳ね上がり、閑散期には安くなる——だが、予算管理面では不透明さが増す。

### 企業側への影響

月額制からトークン消費ベースへの移行は、大型企业にとってはより柔軟なコスト管理が可能になる面もある。実際の使用量に基づく課金は、高利用率のチームと低利用率のチームで公平な費用負担につながる。

ただ、この料金体系変更の背景には、MicrosoftのCopilot事業における収益構造最適化があるとも言われている。AI coding Assistant需要が爆発的に増加する中で、使用量に基づいた課金はより効率的な収益モデルとされる。

## AIエージェントの本当のボトルネック——権限とガバナンス

VentureBeatが5月29日に伝えた興味深い調査がある。エンタープライズAIエージェントの展開において、モデル性能ではなく、権限と承認の層が実際のボトルネックになっているという新しい発見だ。

### Workdayの「Sana」アプローチ

Workdayは、AIエージェントがアクセスできるリソースとアクションを制御する新しい製品を開発している。Gerrit Kazmaier氏（Workday製品・技術社長）は取材に対し、「DIYでAIを構築しようとする企业在最も苦労するのは、まさにここです——何ができるようにするか、という権限の設定です」と語った。

Workdayの答えはシンプルだ——既存のシステム・オブ・レコード（ERP/HR/Financeの管理データベース）を、エージェントのガバナンス層として機能させる。エージェントが何かしようとするたびに、その権限をワークデイシステムの中で検証する。

### なぜ「正確さ」がHRとFinanceで特別難しいのか

Kazmaier氏によると最大の課題は正確さの保証だった。「ほぼ正しいでは足りない」と彼は言う。給与計算、決算、仕事のスケジューリングにおいて、小さなエラーが大きな問題につながる。

一般的なAIアプリケーションと比較して、HRとFinance領域では「正確さの評価」が難しい。ポリシーの設定、ロールベースのセキュリティ、組織の階層構造が複雑に絡み合っていて、一つの小さな設定ミスが連鎖的に影響する。従来のLLM評価手法では、この複雑さを十分にハンドリングできない。

### 権限とアイデンティティは同じ問題

Workdayの調査報告によると、正確さとアイデンティティは本质上同じ問題だという。システムが、エージェントについて、授权する人間について、現在のレコードの状態について十分な知識を持つかどうかに正確性がかかる。

これはAIエージェント設計における根本的な課題を示している。エージェントの「性能向上」ではなく、「権限管理と監査」という領域が、エンタープライズAIの本当の拡張障壁になっている。

## Salesforce、開発組織全体のClaude Code移行で生産性79%向上

The Decoderが報じた別の事例として、Salesforceが開発組織全体をAnthropicのClaude Codeに移行し、驚異的な生産性向上が見られたという報告がある。

### 数字が示す成果

Salesforceの報告によると、2026年4月時点で以下の成果が得られた：

- **開発者1人あたりのプルリクエスト数：79%増加**
- **デプロイメント速度：5倍高速化**
- **コードレビュー時間の大幅な短縮**

注目すべきは、Salesforceは「トークン制限なし」でClaude Codeを導入したことでこれらの成果を獲得した点だ。许多企业在AIツール試験時に利用量制限を設定する做法是不同的这一点は、従来のAI導入アプローチとは異なる新しい戦略を示している。

### トークン制限なしの戦略

多くの企业では、AI coding Assistantの導入初期にトークン消費を厳しく管理する。だがSalesforceのアプローチは逆だった。制限なく使える環境の中で、开发者たちはより自由度高くAIを活用し、本質的な生産性向上が得られた。

これは、AIツール導入における新しいパラダイムを示している。コスト管理より、開発者の生産性向上が優先されるシーンでは、トークン制限なしの環境のほうが効果的な場合がある。

## LLMShare攻撃——ChatGPTとClaudeの共有リンクを悪用したマルウェア配布

Security企業Push Securityが報告した新しいセキュリティ脅威がある。ChatGPTとClaudeの公開共有会話を悪用したマルウェア配布攻撃だ。

### 攻撃の手口

ChatGPTもClaudeも、ユーザーは会話をURLで公開できる。攻撃者はこの機能を悪用它、公式の障害通知やインストールガイドを装った共有会話を作成する。被害者がこれらのリンクを発見するのは大部分、有料検索結果からだ。

新しい手口として、ChatGPTのコード描画機能を使ったフル假冒エラーページの構築がある。受害者がリンクにアクセスすると、本物のエラー画面のように見えるが实际上是マルウェアが配布される。

### 「LLMShare」という命名

Push Securityはこの攻撃技術を「LLMShare」と命名した。BleepingComputerとKasperskyの両社が類似したキャンペーンを文書化している。

AI coding Assistantの共有機能が、マルウェア配布のチャネルとして悪用されている。これは开发者がAIツールを使う上で認識しておくべき新しいセキュリティリスクだ。

## OpenAI Codex、Windows 11とモバイルに「Computer Use」を拡張

OpenAIはCodexアプリケーションの拡張を進めている。Windows 11向け「Computer Use」と、iOS/Android向けモバイルアクセスが追加された。

### Computer Useの展開

Codexの「Computer Use」機能は、AIがユーザーの代わりにPC上のアプリやファイル、他のリソースを利用できるようにする。ユーザーがPCの前にいない状態でも、Codexが代わりにタスクを実行できる。

この機能はすでにmacOS版が4月にローンチされ、Windows版はその後継として展開された。モバイル経由では、iPhoneとAndroidのChatGPTアプリから、Windowsマシンのタスクを開始・監視できるようになっている。

### OpenAIの「super app」戦略

Codexの急速な拡張は、OpenAIが「super app」構築を目指す戦略の一部だ。仕事と日常生活のための統合AIプラットフォームの構築に向けて、ChatGPTはその中核プロダクトになる可能性が高い。

ただ、ChatGPTのブランドは強すぎて、OpenAIのsuper app戦略の中でブランド自体が飲み込まれる可能性は低いとも指摘されている。

## OpenAI、o3とGPT-4.5の提供終了を発表

OpenAIは、古いモデルの提供終了計画を明らかにした。

- **o3**: 2026年8月26日提供服务終了（90日間sunset期間）
- **GPT-4.5**: 2026年6月27日提供服务終了（30日間sunset期間）

また、最近リリースされたGPT-5.5 Instantの更新も予定されている。回答がより自然に、読みやすく、より構造化され、長い箇条書きが少なくなるとされている。

モデル提供終了の影響は、開発者が特定のモデルに依存したアプリケーションを構築している場合、移行準備が必要になることにある。AI SDKのバージョン管理とモデルの抽象化の重要性が化している。
